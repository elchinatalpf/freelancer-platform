# 0.6 · CI on GitHub Actions
Phase 0 · Model Sonnet · Branch kit/0.6-ci (kit/, because this step adds the guard that fails step/ PRs touching `.github/`) · Issue #9

## Goal
After this step, GitHub checks every pull request and every change to `main` by itself: types, code rules and fast tests, a browser test, tests against a real Postgres 18 database, a check for packages with known security flaws and a scan for leaked keys, summed up in one check, `ci-ok`, that must pass before anything merges. It also rejects a pull request whose kind of branch may not change the files it changes, which the local hook cannot promise, because it sees Claude Code's file edits but not its shell commands (PR #2, finding S4).

## Security
- Shell commands (`sed -i`, `cp`, `git mv`, `git checkout <ref> -- <path>`) get past protect-paths, which matches only the file tools; the hook stays that way, and CI is the backstop (S4) -> guard; tests 2, 3 and 8.
- A PR runs its own copy of the workflow and the guard: GitHub takes both from the merge commit, required workflows exist only for organization and enterprise rulesets (GitHub docs, 2026-11-26), and the trigger that would run main's copy for a PR, `pull_request_target`, is forbidden. So the guard catches slips, not a deliberate rewrite of `.github/`, and no test covers that. Backstop: the owner reads the whole diff of any PR that touches `.github/` (the PR template asks), and the ruleset takes `ci-ok` only from GitHub Actions (owner step 1). Running main's copy of the guard is rejected (mine): a PR that edits the script can edit the workflow too, and the old rules would judge a kit/ PR that changes them.
- A fork naming its branch `kit/...` to get the kit/ rules -> the guard fails every PR from outside this repository (owner, 2026-11-26); test 3.
- Weakening the done-gate through `package.json` -> check and every script it calls are pinned (owner, 2026-11-26); test 2. Gap: the tool configs they read (`eslint.config.mjs` with the ADR 1 rule, the Vitest configs, `knip.config.ts`, `tsconfig.json`, `.prettierignore`) stay editable on step/ branches; the reviewer watches them.
- Untrusted text (branch and file names, PR titles) reaching a shell -> no `${{` in `run:`, the event file parsed in Node, `-z`; tests 3 and 4.
- PR code, forks included, getting a write token or a secret -> read-only token, no secrets, `persist-credentials: false`; test 4. A PR's caches are scoped to its merge ref, so it cannot poison main's pnpm store (GitHub docs).
- A secret in public logs or artifacts -> `--redact`, a dummy `APP_URL`, a test-only password; test 6. Today's history is clean: gitleaks 8.30.1 found no leaks (2026-11-26, a mirror clone of every branch, scanned locally).
- A PR silencing the secret scan -> the pre-check and `--ignore-gitleaks-allow`; test 6.
- A known-vulnerable dependency -> audit. On 2026-11-26 `pnpm audit --audit-level high` exits 0; it lists 5 moderate advisories, all under `@stryker-mutator/core` (qs through typed-rest-client, and minimatch). A new high one, or a gitleaks finding, turns CI red: stop and ask. No ignore, allowlist or `pnpm-workspace.yaml` change without the owner.
- A skipped or cancelled job passing as green -> ci-ok fails on any result but `success`; test 5.

## Out of scope
- A mutation job (`pnpm test:mutation` exits 1 until `src/server/` has code), Vercel (0.7), Dependabot version updates, caching beyond the pnpm store (pnpm/setup also keeps a small lockfile-verification cache, with no off switch), scheduled or manual runs, integration tests in `pnpm check` (1.2).
- Other prefixes, such as `dependabot/`, fail the guard until a kit PR adds a rule.
- Gate fixes: Agent kit prompt 6 branches `step/<n>.fix-<slug>` from `redteam/phase-<n>`, so a fix PR opened before the red-team PR merges carries `tests/security/` and fails the guard. The Phase 1 gate settles the order.
