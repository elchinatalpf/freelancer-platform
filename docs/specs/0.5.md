# 0.5 · Quality tooling
Phase 0 · Model Sonnet · Branch step/0.5-quality-tooling · Issue #4

## Goal
After this step, one command, `pnpm check`, checks types, code rules, formatting and unused code and runs the fast tests, and Claude Code cannot finish a step while it fails. The step also adds the tools later steps rely on: browser tests of the running site, mutation tests that show whether our tests would notice a broken line, and a rule that only code in `src/server/` may import the database client.

## Acceptance tests
1. Given the branch, when `pnpm check` runs, then it runs typecheck, lint, format:check, knip and the unit tests and exits 0, and its script matches the string above word for word.
2. Given a fresh clone after `pnpm install --frozen-lockfile`, with no Docker, no `.env.local` and `APP_URL` unset, when `pnpm check` runs, then it exits 0.
3. Given a deliberately failing unit test, when `pnpm check` runs, then it exits non-zero; the PR shows the output, and the test is reverted.
4. Given the real `eslint.config.mjs` through the ESLint Node API, when `lintText` lints an import of each of `@neondatabase/serverless`, `drizzle-orm`, `drizzle-orm/neon-serverless`, `pg` and `postgres` as the virtual file `src/features/x/a.ts`, then each result has a message with ruleId `no-restricted-imports`; as `src/server/db.ts`, none does. Assert on ruleId only; the test lists the five names itself.
5. Given `getHealth`, when called, then it returns exactly `{ status: "ok" }`.
6. Given nothing on port 3100, when `pnpm test:e2e` runs, then in Chromium `GET /api/health` returns 200 and the home page shows its heading.
7. Given the canary, when `pnpm test:mutation --mutate src/features/health/get-health.ts` runs, then the mutation score is above 0 and tests run per mutant is above 0.
8. Given the finished branch, when `pnpm format` runs, then `git status --porcelain` is empty, and `git diff --name-only origin/main...HEAD` lists no must-not-change file; `pnpm-workspace.yaml` may appear, with only the `fsevents: false` line and its comment added.
9. Given an empty `src/server/`, when `pnpm test:mutation` runs with the config as written, then the PR records what Stryker does (exit code, message). The PR also records the measured time of `pnpm check`.
10. Given no tests under `tests/integration/` or `tests/security/`, when `pnpm test:integration` runs, then it exits 0; test:unit has no `--passWithNoTests`.
11. Given a temporary test in `tests/integration/` that imports `getHealth` and always fails (so `pnpm test:integration` fails), when the canary of test 7 runs, then it still succeeds, which shows Stryker runs only the unit project; the test is then removed (never placed in `tests/security/`), and the PR records both results and how the limit is enforced (runner option or `vitest.unit.config.ts`).

## Security
- App code imports the database client outside `src/server/`, skipping the Data Access Layer (ADR 1) -> test 4, inside check. Gap: the rule sees static imports and re-exports, not `import()` or `require()` (ESLint 9.39.5); the reviewer covers those.
- Tests or tools read real secrets from `.env.local`, or pass only because it exists -> test 2; dummy `APP_URL` in `test.env`, `webServer.env` and the typecheck script.
- Stryker copies the project into `.stryker-tmp/`, where the Read deny rules for `./.env.local` do not reach -> `ignorePatterns` `.env*`; test: run test 7 with cleanTempDir off, then no `.env*` file exists under `.stryker-tmp/`.
- New packages widen the supply chain -> exact versions under the `pnpm-workspace.yaml` policy, changed only by the approved `fsevents: false` (allowBuilds never true); the frozen install in test 2.
- A tool that rewrites files bypasses protect-paths, which sees only Edit and Write -> only `format` rewrites source (no `--fix` in any script), and `.prettierignore` covers the protected paths; test 8.
- Done-gate (PR #2 N9): once the branch is ahead of `origin/main`, every Stop runs check, even after a turn that only answered a question; a run past 600 s is killed and Claude may stop -> check runs no Docker, database, build or browser; test 9 records its time. Step 1.2 decides how integration fits.
